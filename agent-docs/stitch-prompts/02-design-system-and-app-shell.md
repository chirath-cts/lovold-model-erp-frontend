# Prompt 02: Design System And App Shell

Paste this after Prompt 01, inside the same Stitch project.

```md
Continue the Lovold ERP project and keep the same visual direction.

Now design the shared app shell and reusable patterns that all later screens should inherit.

Create the foundational UI system for a desktop-first internal ERP:

- persistent left navigation
- top app header
- page title and action bar pattern
- filter and search bar pattern
- summary metric cards
- status badges
- table layout pattern
- detail drawer or right-side detail panel pattern
- modal and form pattern
- empty state pattern
- error state pattern
- no-results state pattern
- timeline or progress-tracker pattern
- ETA breakdown card pattern

The design system should support these recurring states and concepts:

- products vs components
- stock quantity vs reserved quantity vs available quantity
- order statuses
- supplier PO statuses
- delayed vs on-track
- risk states such as low available stock or inbound dependency

Define a clear visual language for status-heavy workflows:

- neutral informational status
- warning status
- delayed or blocked status
- success or completed status
- in-progress status

Use realistic enterprise UI density. Prioritize clarity, scannability, and structured layouts over decorative spacing.

If the shell includes imagery, illustrations, empty-state art, or sample content, keep it domain-relevant:

- aquaculture engineering
- marine industrial systems
- feed barges
- control rooms
- pipe systems
- industrial sensors

Avoid generic startup-dashboard aesthetics and generic e-commerce placeholder content.

Do not redesign login in detail. Focus on the reusable operational shell and patterns that will power all major sections.
```
