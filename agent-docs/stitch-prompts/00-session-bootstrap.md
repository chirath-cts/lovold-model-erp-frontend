# Prompt 00: Session Bootstrap

Paste this first into Stitch before using the rest of the prompt pack.

```md
We are designing one product inside one continuous Stitch project: Lovold ERP.

This is a desktop-first internal ERP application for Lovold staff. It is not a customer-facing storefront.

Important instruction for the rest of this session:

- preserve continuity across all later prompts
- keep the same visual language, layout rhythm, spacing system, type hierarchy, navigation shell, table style, status-badge system, and interaction patterns
- do not redesign the product from scratch on each prompt
- treat later prompts as additions and refinements to the same product
- maintain a consistent enterprise ERP feel across all sections

The product should feel:

- data-dense but clear
- operational and trustworthy
- status-heavy
- built for daily internal use
- optimized for overview plus drill-down
- grounded in industrial aquaculture operations rather than generic retail or generic SaaS

Critical domain truths that must remain consistent across all later screens:

- products and components are different item types
- components are built from products
- customer pricing applies only to products
- reserved stock is not available stock
- orders can contain products or components
- confirmed orders trigger reservation and stored ETA planning
- inbound supplier purchase orders affect order ETA when stock is missing
- ETA visibility is a first-class part of the product
- example content should feel like Lovold's aquaculture engineering business

For every later prompt, preserve continuity unless explicitly told otherwise.

Acknowledge this design continuity and then continue with the next prompt.
```
